# 修复最新实验中护栏过严与教学死锁问题 Spec

## Why
根据最新实验结果与日志（`summary_metrics.csv`、`app.log`、`turn_logs.jsonl`等）的全面分析，系统在引入 `FSM+Guardrail` 后认知矫正率跌至 0.00%，绝大部分对话陷入“认知僵局”并耗尽最大轮数。主要原因是 LLM Judge 护栏判定过于严苛，将必要的事实铺垫和基础原理解释也判定为“直接给答案”从而拦截；同时助教在面对学生严重挫败或明确索要答案时，缺乏降级干预策略，导致机械反问和类比滥用，造成教学死锁。

## What Changes
- 优化 `src/guardrails.py` / `src/llm_judge.py` 中的 LLM Judge 提示词：明确区分“提供基础物理事实/原理”与“直接给出最终答案/代替推理”，放宽对基础知识铺垫的拦截标准。
- 优化 `src/generator.py` 中的生成提示词（或 `src/router.py` 中的路由策略）：当学生多次表达挫败、明确索要答案或长时间处于“认知僵局”时，允许助教采取“降级干预策略”（如直接解释部分概念 + 引导验证），而不是一味拒绝和反问。
- 优化类比使用策略：在提示词中增加“若学生对类比表现出困惑或排斥（如‘电不是水’），应立即停止该类比，转向直观现象或逻辑推导”的指令。

## Impact
- Affected specs: 教学有效性、认知矫正率、护栏拦截准确率、用户体验
- Affected code: `src/llm_judge.py` (或 `src/guardrails.py`), `src/generator.py`

## ADDED Requirements
### Requirement: 柔性降级干预策略
系统 SHALL 在学生表现出严重挫败或多次处于认知僵局时，提供更为直接的脚手架支持，避免陷入无效的机械反问循环。

#### Scenario: 学生极度挫败并索要答案
- **WHEN** 学生多次回答“不知道”或明确要求“直接告诉我结论”，且当前状态处于 S5 认知僵局。
- **THEN** 助教应在安抚情绪后，给出部分直接的物理解释或事实铺垫，再就下一步进行轻量级提问，而不是单纯地用模板拒绝。

## MODIFIED Requirements
### Requirement: 护栏拦截标准放宽
LLM Judge SHALL 仅拦截“直接给出本题最终结论”或“完全代替学生完成关键逻辑推理”的行为，允许助教提供必要的物理定义、公式或客观实验现象作为推理前提。
