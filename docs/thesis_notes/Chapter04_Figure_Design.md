## 图 1：电学与浮力典型迷思概念的图谱化表征示意 (`fig:misconception-graph`)

**1. 绘图目标**
展示系统如何将抽象的“知识点”转化为可计算的“主题—迷思类型—诊断线索—推荐策略”图谱结构。这不是一张表格，而是一个知识图谱（Knowledge Graph）的局部切片。

**2. 推荐排版与图表类型**
- **类型**：树状展开图或关联图谱。
- **布局**：从左至右或从中心向四周辐射。
- **配色**：
  - 中心主题（深蓝色）：浮力 / 电学
  - 迷思类型（橙色）：压强经验误投射 / 序列衰减观等
  - 诊断线索（绿色边框，对话框样式）：“水越深压强越大，所以浮力越大”
  - 推荐策略（紫色边框，带执行图标）：后果探索（归谬）

**3. 核心节点与连线内容（以“浮力”切片为例）**
- **根节点**：【主题】浮力
  - **分支 A（迷思类型）**：压强经验误投射
    - 关联线（包含属性）：*表现为* -> 【诊断线索】“越深浮力越大”
    - 关联线（包含属性）：*映射至* -> 【推荐策略】后果探索（归谬）
  - **分支 B（迷思类型）**：单因归因错误
    - 关联线（包含属性）：*表现为* -> 【诊断线索】“重物必沉”
    - 关联线（包含属性）：*映射至* -> 【推荐策略】挑战（极端反例）

## 图 2：融合教学感知与动态干预决策的对话架构 (`fig:teaching-architecture`)

**1. 绘图目标**
展示对话系统的5个分层架构，以及一次完整输入输出的链式处理流程（闭环）。重点体现“在生成之前融入感知与决策”。

**2. 推荐排版与图表类型**
- **类型**：分层架构图（Layered Architecture）叠加数据流（Data Flow）。
- **布局**：背景为5个水平横向的“层（Layer）”，前景有一条贯穿这些层的“箭头链”。

**3. 层次划分（背景，从下到上或自顶向下排列）**
- **教学感知层**：主题线索、概念实体、情感信号提取
- **诊断决策层**：迷思状态诊断、教学阶段判定
- **知识调用层**：迷思概念库、策略模板库、案例库检索
- **生成执行层**：苏格拉底式引导生成
- **安全约束层**：输入意图拦截、输出认知卸载审查

**4. 核心流向链（前景箭头连接）**
学生表述观点 -> (经过感知层)语义与情感解析 -> (经过决策层)迷思状态诊断 -> 教学阶段判定 -> (经过知识层)干预策略调用 -> (经过生成层)苏格拉底式引导生成 -> (经过安全层)安全与认知卸载审查 -> 界面反馈给学生
*(注意：需要有一条虚线箭头从“界面反馈给学生”指回“学情状态回写”，形成回路。)*

## 图 3：阶段化教学对话控制与状态流转示意 (`fig:state-flow`)

**1. 绘图目标**
明确区分“教学推进主线（T1-T5）”与“安全护栏分支（G1-G4）”，并展示对应的工程状态（S0-S8）流转路径。

**2. 推荐排版与图表类型**
- **类型**：双轨状态机流程图（State Machine Flowchart）。
- **布局**：上下双轨设计。上方为主轨道（教学主线），下方为副轨道（护栏分支）。

**3. 节点定义与连线（必须包含如下文本与编号）**
- **起点**：学生输入
- **主轨道（教学推进主线，绿色/蓝色块）**：
  - T1 进入与定题 (`S0 进入与分析`) -> T2 迷思诊断 (`S3 迷思诊断`) -> T3 认知冲突 (`S4 认知冲突`) -> T4 支架过渡 (`S5 支架式引导`) -> T5 验证与闭环 (`S6 验证与加深`) -> 终点 (`S7 事实兜底`)
- **副轨道（安全护栏分支，橙色/红色块）**：
  - G1 安全检查 (`S1 护栏检查`)
  - G2 拒绝与重定向 (`S2 拒绝与引导`)
  - G3 防环与降级 (`ANTI_LOOP_RULES` 触发点)
  - G4 确认并结束 (`S8 确认并搁置`)

**4. 关键连线（标明触发条件）**
- **正常推进**：S0 -> S3 -> S4 -> S5 -> S6 -> S7
- **输入拦截**：学生输入优先经过 S1，若有直接索答/偏题意图，流向 S2，再由 S2 返回 S3。
- **防环降级回退**：若在 S4 处出现“连续卡顿/负面情绪”，则触发 `ANTI_LOOP_RULES`，强制降级流向 S5；若 S5 循环过深，则降级流向 S7。
- **异常终止**：若多轮无效互动，流向 S8 结束。

## 图 4：教学功能构成与诊断—干预闭环结构图 (`fig:prototype-modules`)

**1. 绘图目标**
展示系统 6 个核心模块之间的信息交互闭环，特别突出“学情记录”、“状态回写”和“输出审查”在维持教学一致性中的作用。

**2. 推荐排版与图表类型**
- **类型**：模块关系图（Component Interaction Diagram）。
- **布局**：环形或 2x3 网格排布。

**3. 模块清单（方框）**
- 1. 学生输入解析模块
- 2. 迷思诊断模块
- 3. 阶段控制模块
- 4. 知识策略映射模块
- 5. 干预生成与审查模块
- 6. 学情记录与反馈展示模块

**4. 关键交互标记**
- 箭头：`模块1 -> 模块2 -> 模块3 -> 模块4 -> 模块5 -> 模块6`，最后 `模块6` 提供反馈给学生。
- 重点标识：
  - 在 `模块5` 处标明一个红色的放大镜图标或检查站：“输出审查（防直接给答）”
  - 从 `模块6` 引出一条长虚线指向后端的数据库/缓存：“学情记录与状态回写”
  - 从“学情状态”引出虚线反哺给 `模块2` 和 `模块3`，表示下一轮诊断依赖历史状态。

## 图 5：教学阶段推进逻辑与知识策略映射示意 (`fig:kb-state-flow`)

**1. 绘图目标**
揭示知识图谱与策略库并不是静态的“查字典”，而是嵌入在教学阶段流转中被动态调用的过程。重点体现“高置信推进”与“低置信回退”。

**2. 推荐排版与图表类型**
- **类型**：带判断节点的循环流程图（Decision Tree Flowchart）。
- **布局**：以“阶段判断”菱形为中心，辐射向不同的知识库调用动作。

**3. 图表内容**
- **顶部四大资源库（圆柱体/文件图）**：
  1. 迷思特征提取库
  2. 干预策略模板库
  3. 微支架与动态提示词生成模板
  4. 阶段转换与回退规则
- **中部处理循环**：
  - 当前学生状态 + 历史状态 $\rightarrow$ 【阶段判断 (菱形)】
- **判断分支**：
  - **分支 A（高置信推进）**：学生解释明确/完成验证 $\rightarrow$ 调用【干预策略模板库】(进入下一步冲突或迁移)
  - **分支 B（低置信回退/卡顿）**：诊断不明或遭遇高认知负荷 $\rightarrow$ 调用【微支架与动态提示词生成模板】(提供类比或思想实验)
  - **分支 C（异常终止）**：反复无进展 $\rightarrow$ 调用【阶段转换与回退规则】转介结束
- **底部闭环**：
  - 根据调用的库资源生成对话 $\rightarrow$ 【阶段更新】 $\rightarrow$ 回到循环起点。

## 图 6：“不直接给答”约束的系统化实现与界面展示示意 (`fig:no-direct-answer-ui`)

**1. 绘图目标**
把抽象的“不直接给答”机制具象化为两部分：系统后台的四重约束机制，以及前端展示给学生的 UI 视觉反馈。

**2. 推荐排版与图表类型**
- **类型**：左右对比图 / 机制剖面图 + UI Mockup（线框图界面模拟）。
- **布局**：左侧为系统机制（漏斗式或层层过滤），右侧为模拟的学生交互界面。

**3. 图表内容**
- **左侧（系统化实现：防卸载漏斗机制）**：
  - 第 1 层（生成前）：阶段动作约束（仅限澄清、追问、类比等）
  - 第 2 层（生成中）：模板控制（问题优先、提示为辅）
  - 第 3 层（生成后）：输出审查（拦截直接结论、完整求解）
- **右侧（界面展示示意：手机/网页对话框 Mockup）**：
  - **系统横幅提示**：“我可以陪你一起想，但不会直接把答案交给你”（非直接作答契约说明）。
  - **对话气泡 1（学生）**：“你直接告诉我浮力公式吧。”
  - **对话气泡 2（系统，带盾牌/护栏图标）**：“我们一起来推导它。你觉得如果在深水和浅水里……”（体现引导式反馈与提示性追问）。
  - **底部组件**：可显示“受控思想实验加载中…”或类似的“有限支架”按钮标识。
