## 图 1：电学与浮力典型迷思概念的图谱化表征示意 (`fig:misconception-graph`)

**1. 绘图目标**
展示系统如何将抽象的“知识点”转化为可诊断、可干预的教学知识结构（对应课标“科学思维”素养的证据捕捉）。

**2. 推荐排版与图表类型**
- **类型**：树状展开图或关联图谱。
- **布局**：从左至右或从中心向四周辐射。
- **配色语义**：
  - 领域知识（深蓝色）：核心物理主题
  - 认知偏差节点（橙色）：典型迷思类型
  - 用户话语特征（绿色边框，气泡样式）：学生前概念的自然语言表达
  - 教学动作映射（紫色边框，圆角矩形）：匹配的苏格拉底式策略

**3. 核心节点与连线内容**
- **根节点**：【主题】浮力 / 电学
  - **分支 A（迷思类型）**：压强经验误投射 (浮力)
    - 关联线属性：*表现为* -> 【诊断线索】“因为水越深压强越大，所以浮力也越来越大”
    - 关联线属性：*映射至* -> 【推荐策略】后果探索（归谬）
  - **分支 B（迷思类型）**：单因归因错误 (浮力)
    - 关联线属性：*表现为* -> 【诊断线索】“铁块比木块重得多，所以铁块肯定会沉”
    - 关联线属性：*映射至* -> 【推荐策略】挑战（极端反例）
  - **分支 C（迷思类型）**：序列衰减观 (电学)
    - 关联线属性：*表现为* -> 【诊断线索】“前面的灯泡把电用掉了一部分，后面的灯就暗了”
    - 关联线属性：*映射至* -> 【推荐策略】证据追问 / 思想实验
  - **分支 D（迷思类型）**：电流消耗观 (电学)
    - 关联线属性：*表现为* -> 【诊断线索】“电从电池出来到灯泡就被用掉了，所以不用回去”
    - 关联线属性：*映射至* -> 【推荐策略】类比支架

**4. 图注建议**
*“该图展示了系统如何将教材知识点转化为可诊断、可干预的教学知识结构，从而为后续的苏格拉底式提问提供锚点。”*

## 图 2：融合教学感知与动态干预决策的对话架构 (`fig:teaching-architecture`)

**1. 绘图目标**
展示系统宏观层面“教学感知—诊断—干预—审查”的闭环链路，强调在回复生成前对学生理解状态的感知与意图决策。

**2. 推荐排版与图表类型**
- **类型**：宏观教学链路图。
- **布局**：水平流水线布局，从左到右贯穿核心教学层。

**3. 层次划分（弱化软件分层，突出教学属性）**
- **感知层 (Perception)**：提取学生意图、情感信号、认知僵局
- **决策层 (Decision)**：迷思状态诊断、教学阶段判定
- **知识层 (Knowledge)**：匹配策略目标、调取防环规则
- **生成层 (Generation)**：执行苏格拉底式引导生成
- **审查层 (Guardrail)**：风险意图拦截、认知卸载审查

**4. 核心流向链**
学生表述观点 $\rightarrow$ (经过感知层) 语义与情感解析 $\rightarrow$ (经过决策层) 迷思诊断与阶段路由 $\rightarrow$ (经过知识层) 匹配教学动作 $\rightarrow$ (经过生成层) 组装提示并生成回复 $\rightarrow$ (经过审查层) 防直接给答审查 $\rightarrow$ 界面反馈给学生
*(引出一条虚线箭头从“界面反馈”指向“学情状态回写”，形成教学闭环。)*

**5. 图注建议**
*“该架构体现了‘先感知学生状态，再决策教学动作’的教育智能体设计理念，而非简单的问答映射。”*

## 图 3A：教学阶段推进主线图 (`fig:state-flow-main`)

**1. 绘图目标**
展示系统如何随着学生认知状态的变化，从迷思诊断逐步推进到概念重构，体现苏格拉底式教学的核心步骤。

**2. 推荐排版与图表类型**
- **类型**：单向或阶段推进式状态图。
- **布局**：从左至右或从上到下的阶梯式递进。

**3. 节点定义与连线**
- **起点**：学生输入
- **教学推进主线（绿色/蓝色块）**：
  - T1 进入与定题 (Listen & Analyze) $\xrightarrow{\text{初步感知}}$ 
  - T2 迷思诊断 (Misconception Diagnosis) $\xrightarrow{\text{定位迷思类型}}$ 
  - T3 认知冲突 (Cognitive Conflict) $\xrightarrow{\text{冲突生效}}$ 
  - T4 支架过渡 (Scaffolding Guidance) $\xrightarrow{\text{完成部分解释}}$ 
  - T5 验证与闭环 (Verification Deepening) $\xrightarrow{\text{自我解释通过}}$ 终点 (Fact Grounding)

**4. 图注建议**
*“该图展示了理想状态下，系统引导学生完成概念转变的五个核心教学阶段。体现了对‘证据捕捉、冲突引发、知识重构’等科学思维素养的支持。”*

## 图 3B：安全护栏与防环干预图 (`fig:state-flow-guardrail`)

**1. 绘图目标**
展示系统在面临异常交互（如直接索答、偏题）或教学困境（如认知死锁、深度卡顿）时的兜底控制与回退机制。

**2. 推荐排版与图表类型**
- **类型**：带回退与拦截分支的状态机局部图。
- **布局**：以“护栏分支”和“降级回退”为主体，辅助以虚线连接。

**3. 节点定义与跨轨连线**
- **异常拦截分支（橙色/红色块）**：
  - G1 护栏检查 (Guardrail Check) $\xrightarrow{\text{检测到违规意图}}$ G2 拒绝与重定向 (Refusal & Guidance) $\xrightarrow{\text{引导回正轨}}$ 迷思诊断
- **防环降级机制（黄色块与虚线）**：
  - **冲突降级**：从“认知冲突阶段”引出虚线 $\rightarrow$ “支架过渡阶段”
    - *触发条件*：连续多轮冲突未推进，或检测到学生明显焦虑/挫败。
  - **支架降级**：从“支架过渡阶段”引出虚线 $\rightarrow$ 兜底终点 (Fact Grounding)
    - *触发条件*：连续三轮支架引导无效。
- **异常终止**：
  - **会话结束**：兜底阶段连续卡顿 $\rightarrow$ 确认并搁置 (Acknowledge & Park)，终止当前知识点干预。

**4. 图注建议**
*“为防止对话失控或学生产生严重认知负荷，系统设计了前置意图护栏与后置认知死锁降级机制，确保教学过程的平稳可控。”*

## 图 4：教学功能构成与诊断—干预闭环结构图 (`fig:prototype-modules`)

**1. 绘图目标**
展示系统中观层面的功能模块如何围绕“学情状态”进行协同，突出“形成性评价”与“状态回写”在维持教学连贯性中的作用。

**2. 推荐排版与图表类型**
- **类型**：模块交互与数据闭环图（Component Interaction Diagram）。
- **布局**：环形布局，中心为“学情状态库（Session Memory）”。

**3. 模块清单与交互逻辑**
- **中心节点**：学情状态库 (Session Memory) - 记录历史迷思、已用策略与当前情感。
- **M1. 学生输入解析模块**：感知多维特征。
- **M2. 迷思诊断模块**：结合当前输入与中心历史状态，输出诊断标签。
- **M3. 阶段控制模块**：基于诊断结果，规划下一步教学动作。
- **M4. 知识策略映射模块**：动态拉取对应的教学提示词模板。
- **M5. 干预生成与审查模块**：生成引导式回复，并执行“防直接给答”审查。
- **M6. 学情记录与反馈展示模块**：向前端输出回复，同时将本轮新状态回写至中心“学情状态库”。

**4. 闭环连线逻辑**
- 外圈主连线：`M1 -> M2 -> M3 -> M4 -> M5 -> M6 -> 用户`
- 内圈反馈连线：M6 引出虚线 `状态回写 (State Update)` 指向中心的学情状态库。M1、M2、M3 均有箭头从中心库拉取历史学情。

**5. 图注建议**
*“该图展示了系统各功能模块如何围绕中心‘学情状态库’形成诊断与干预闭环，确保每一次提问都建立在学生真实认知历史的基础上。”*

## 图 5：教学策略随认知阶段动态映射示意 (`fig:kb-state-flow`)

**1. 绘图目标**
揭示系统的知识策略库不是静态查表，而是根据学生的“高置信推进”或“低置信回退”进行动态映射（支持元认知参与）。

**2. 推荐排版与图表类型**
- **类型**：策略动态调用流程图。
- **布局**：以“阶段与策略路由判断”为中心，向两侧或下方辐射。

**3. 图表内容与节点映射**
- **顶部教育资源库**：
  1. 迷思特征库
  2. 策略目标库
  3. 阶段策略候选池
  4. 状态转移规则库
- **中部动态决策**：
  - 当前感知 + 历史学情 $\rightarrow$ 【阶段与策略路由判断】
- **判断分支**：
  - **分支 A（理解推进）**：学生解释明确 $\rightarrow$ 提升认知要求 $\rightarrow$ 调用【阶段策略候选池】获取高级策略（如后果探索）。
  - **分支 B（认知僵局）**：学生诊断不明或多次停滞 $\rightarrow$ 降低认知负荷 $\rightarrow$ 强制调用【微支架策略】（如类比支架或线索追踪）。
  - **分支 C（兜底终止）**：超出系统干预边界 $\rightarrow$ 强制调用【结束规则】，提示向教师求助。
- **底部闭环**：
  - 将匹配的策略注入生成器 $\rightarrow$ 状态更新。

**4. 图注建议**
*“通过动态感知学生的认知僵局与理解进度，系统在推进主线与提供微支架之间灵活切换，实现因材施教的干预映射。”*

## 图 6：“不直接给答”约束的系统化实现与界面展示示意 (`fig:no-direct-answer-ui`)

**1. 绘图目标**
展示系统如何通过多层防卸载约束，促使学生进行实质性的认知努力（对应课标的科学探究要求），并将后台机制映射为前端温和的教学界面。

**2. 推荐排版与图表类型**
- **类型**：机制剖面图 + UI Mockup（线框图界面模拟）。
- **布局**：左侧为约束机制漏斗，右侧为对应的学生交互界面。中间使用箭头连接，说明“后台约束 $\rightarrow$ 前端引导”。

**3. 图表内容**
- **左侧（系统化实现：防卸载约束漏斗）**：
  - **第 1 层（输入意图拦截）**：拦截直接索答与偏题。
  - **第 2 层（生成前动作约束）**：限制大模型的生成空间（问题优先、提示为辅）。
  - **第 3 层（生成后审查与支架豁免）**：裁判模型拦截泄露答案的行为，但对归谬法、思想实验、正向强化等教育支架予以豁免通过。
- **右侧（界面展示示意：教育场景化 UI）**：
  - **系统横幅提示（顶部契约）**：“我可以陪你一起想，但不会直接把答案交给你。”
  - **对话气泡 1（学生，右侧）**：“你直接告诉我浮力公式吧。”
  - **对话气泡 2（系统，左侧，带护栏图标）**：“我们一起来推导它。如果在深水和浅水里……”（温和拒答与支架引导）。
  - **悬浮组件（右下角）**：当前学习目标：“理解浮力与深度的关系”。

**4. 图注建议**
*“图左侧展示了防止学生产生‘认知卸载’的三层后台漏斗机制，右侧展示了该机制在前端转化为对学生‘温和拒答与支架引导’的具体对话形式。”*
