# SocraticMisconceptionTutor 项目真实问题综合梳理报告 (VERIFIED_PROJECT_ISSUES.md)

经过对两个 AI 评估报告（`project_evaluation.md` 和 `PROJECT_ISSUES.md`）的仔细研读，并与当前代码库 (`src/`, `tests/` 等) 进行交叉验证，确认了以下在当前项目中**真实存在且尚未修复**的核心问题。

为了明确后续重构或论文写作的优化靶点，将这些问题按照**严重（Critical）**、**中等（Moderate）**和**轻微（Minor）**三个优先级进行了梳理。

---

## 🔴 严重问题 (Critical Priority)

这些问题直接破坏了实验结果的公平性、有效性以及数据的纯净度，是任何宣称“系统有效”的论文或报告中必须首先解决的致命伤。

### 1. 标签泄漏与 Baseline 实验不公 (A1)
- **描述**：`tutor_graph.py` 中的 `baseline_node` 不仅直接读取了由 `simulator.py` 在会话开始前强行注入的“真值迷思概念”，还调用了与 FSM 完全相同的 `generate_reply` 函数和 system prompt。
- **影响**：Baseline 本质上变成了“有 FSM 策略引导但固定在 S5 状态的系统”，并非“无策略朴素 LLM”。这严重缩小了不同版本间的性能差异，使得证明 FSM 架构有效性的消融实验结论失效。

### 2. 评估数据被测试会话污染且无隔离 (C2)
- **描述**：`logger.py` 中日志文件（如 `session_summary.jsonl`）使用纯追加（Append-Only）模式写入。`evaluator.py` 统计指标时无差别读取全量日志。
- **影响**：不同批次的实验数据以及开发者本地运行的 `test_session_001` 测试数据被混合在一起计算。这直接导致汇总的 `summary_metrics.csv` 指标失真。

### 3. 实验样本量极度不足与对抗模拟偏差 (E1 & E2)
- **描述**：`simulator.py` 中 `num_runs` 硬编码为 1，每个条件仅生成 1 个样本（共 36 个会话）。同时，模拟学生被强行提示“必须至少尝试一次索要答案或跑题”。
- **影响**：这种人为注入的对抗行为偏离了真实学生的认知惯性；同时，极小的样本量无法支撑任何具备统计显著性（Statistical Significance）的定量结论。

### 4. 认知状态分类缺乏多轮推理 (P1)
- **描述**：`classifiers.py` 要求 LLM 在单次推理中同时完成 5 个复杂维度的分类（意图、概念、认知状态、情感、置信度）。
- **影响**：教育学上，认知状态的转变需要参考多轮上下文趋势。单步判断使得分类结果极易震荡，导致后续的 FSM 路由决策失效。

## 🟡 中等问题 (Moderate Priority)

这些问题暴露了系统在特定边界条件下的防御漏洞，或影响了评估指标（Metrics）的区分度与可靠性。

### 1. 降级策略的运算符优先级 Bug (P5)
- **描述**：`generator.py` 中触发降级干预的条件为 `if decision.state == "S5" and memory.recent_states.count("S5") >= 3 or sentiment == "焦虑/挫败":`。由于 `and` 优先级高于 `or`，实际等价于 `(S5 且卡壳) 或 焦虑`。
- **影响**：这会导致学生在任何状态下只要表现出焦虑，系统就会触发本该在 S5 僵局时才使用的降级支架，打乱教学节奏。

### 2. 护栏存在覆盖盲区与逻辑矛盾 (A2 & Guardrail Gap)
- **描述**：
  1. `tutor_graph.py` 中的 `is_already_safe` 变量命名与实际控制流语义矛盾（判定需要护栏时反而跳过了输入检查）。
  2. `guardrails.py` 在 `misconception_tag` 为空或未知时，直接跳过输出泄露检测。
- **影响**：当 NLU 分类器失效或遭遇未知错误概念时，系统的输出安全防线会完全洞开。

### 3. 核心评估指标定义缺陷 (V1)
- **描述**：`evaluator.py` 中 `Transition Success Rate` 只要路由到 S0-S6 任意合法状态即算成功，导致该指标恒等于 100%；`Identification Accuracy` 的分母只统计了模型输出预测值的轮次。
- **影响**：这些指标缺乏区分度，无法真实反映 FSM 状态转移的顺畅度或分类器的鲁棒性。

### 4. 迷思概念库覆盖面极窄 (P3)
- **描述**：`misconceptions.json` 中仅包含 4 个最基础的物理迷思概念。
- **影响**：这限制了系统的泛化能力，也削弱了实验结论的外部效度（External Validity）。

## 🟢 轻微问题 (Minor Priority)

这类问题属于代码异味（Code Smells）或文档漂移，虽不致命但会影响项目的可维护性与开发者体验。

### 1. 正则匹配过度清理破坏物理公式 (C5)
- **描述**：`generator.py` 中 `re.sub(r'[（\(].*?[）\)]', '', text)` 会无差别删除所有括号及内部内容。
- **影响**：可能误删 LLM 生成的正常物理公式（如 `(F=ma)`），影响教学质量。

### 2. 死代码与不可达分支 (A3)
- **描述**：`tutor_graph.py` 中 `route_after_generate` 硬编码返回 `"guardrail"`。
- **影响**：导致状态图定义中声明的 `"end": END` 分支成为永远不可达的冗余代码。

### 3. 运行入口与文档不一致 (Documentation Drift)
- **描述**：`Code_Wiki.md` 等文档描述的交互式入口与 `main.py` 底部实际默认执行的 `demo()` 函数不符。
- **影响**：给复现实验或新开发者上手带来困扰。
