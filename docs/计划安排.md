- 检索模块复杂度
- 模拟学生复杂程度
- UI/前端
- 长对话记忆优化

## 三、系统实现蓝图（模块、输入输出、数据结构、状态机规则）

### 3.1 实现边界与可行性约束

为保证 5 天内可实现、可测试、可写入论文，本部分以“**最小可执行系统**”为原则，直接对齐开题中的三层架构，但做以下收缩：

- **主题边界固定**：仅覆盖电学、浮力两个主题。
- **迷思概念边界固定**：以本计划已冻结的 4 个迷思点为准，不再新增。
- **知识检索边界固定**：实现时优先采用 `JSON/字典检索`，保留接口，暂不强制实现向量检索。
- **交互形态边界固定**：先完成命令行或脚本化多轮对话，不把前端界面列为必要条件。
- **评估边界固定**：只做功能/安全测试、仿真对话实验、基线与消融对比；不做真实学生试用，不把专家评估作为 5 天内必交付项。

这样处理后，系统仍然保持与开题一致的核心主张：**用显式教学状态机 + 苏格拉底式提问策略 + 防答案泄露护栏，实现对典型迷思概念的启发式干预**。

### 3.2 总体架构与主流程

系统仍采用开题中的三层结构，但实现为 7 个最小模块：

1. **输入分析模块**：识别意图、迷思概念、认知状态、风险标签。
2. **状态路由模块**：根据输入分析结果和会话状态决定下一教学状态。
3. **策略选择模块**：根据状态和迷思概念选择合适提问策略与模板。
4. **知识检索模块**：按迷思标签提取核心科学概念、反例、类比和验证问题。
5. **受控生成模块**：按“身份 + 当前状态 + 策略 + 知识 + 护栏约束”组装生成提示。
6. **护栏模块**：处理输入风险识别、输出审核、必要时重写。
7. **日志评估模块**：记录回合日志与会话汇总，并计算实验指标。

**端到端主流程**

```text
学生输入
  -> 输入分析
  -> 护栏前置检查
  -> 状态路由
  -> 策略选择
  -> 知识检索
  -> 受控生成
  -> 输出审核/必要时重写
  -> 记录日志
  -> 返回回复
```

### 3.3 模块输入输出定义

#### 模块 1：输入分析模块（Perception）

**职责**

- 识别 `intent`
- 识别 `misconception_tag`
- 识别 `cognitive_state`
- 标记 `risk_flag`
- 可选识别 `sentiment`

**输入**

- 当前学生输入文本
- 最近 1–3 轮摘要
- 当前会话主题

**输出**

```json
{
  "intent": "Misconception_Expression",
  "misconception_tag": "M-ELE-001",
  "cognitive_state": "固守错误概念",
  "sentiment": "Confused",
  "risk_flag": false,
  "confidence": 0.84
}
```

**实现建议**

- 第一版优先采用“关键词/规则 + 少量 LLM 判别兜底”的混合方式，避免 5 天内把时间耗在训练分类器上。
- `sentiment` 不是 MVP 必要项，但字段建议保留，缺失时写 `null`，以保持与开题设计兼容。

#### 模块 2：状态路由模块（Decision / FSM）

**职责**

- 根据输入分析结果决定教学状态
- 处理回退、重试、结束条件
- 输出下一步教学目标

**输入**

- 输入分析结果
- 会话运行时状态
- 已使用策略列表
- 当前轮次

**输出**

```json
{
  "state": "S4",
  "state_name": "Cognitive_Conflict",
  "strategy_family": "Assumption_Probing",
  "next_goal": "制造认知冲突，打破原有错误解释",
  "need_guardrail": false
}
```

#### 模块 3：策略选择模块（Strategy Selector）

**职责**

- 从 5 类苏格拉底式策略中选出当前最适合的一类
- 从对应模板池中选择未过度重复的模板

**输入**

- 当前状态
- 迷思概念标签
- 认知状态
- 最近已使用模板

**输出**

```json
{
  "strategy_name": "Consequence_Exploration",
  "template_id": "CE_03",
  "template_text": "如果按你的想法继续推下去，会出现什么结果？"
}
```

**可行性要求**

- 单一模板连续复用不得超过 2 次。
- 若同一策略连续 2 轮无进展，必须触发策略切换或状态回退。

#### 模块 4：知识检索模块（Minimal Knowledge Retrieval）

**职责**

- 按迷思概念返回：
  - 科学概念要点
  - 反例
  - 类比
  - 验证问题

**输入**

- `misconception_tag`
- `strategy_name`

**输出**

```json
{
  "core_science_points": ["串联电路中电流处处相等"],
  "counterexamples": ["若电流被前一个灯泡消耗，后面的灯泡应越来越暗"],
  "analogies": ["把闭合电路类比成封闭水路"],
  "verification_questions": ["如果在同一串联回路不同位置测电流，结果会怎样？"]
}
```

**实现约束**

- MVP 阶段不强制上 RAG。
- 只要数据结构按“可检索”组织，后续即可无缝替换为向量检索或图检索。

#### 模块 5：受控生成模块（Controlled Generation）

**职责**

- 组装提示词
- 生成候选教学回复
- 保证回复遵循当前教学状态与禁泄露规则

**输入**

- 当前状态
- 策略模板
- 知识片段
- 会话摘要
- 护栏约束

**输出**

```json
{
  "raw_reply": "你刚才说电流会被灯泡消耗。那如果前面的灯泡真的把电流用掉了，后面的灯泡应该会出现什么现象？",
  "reply_type": "guiding_question"
}
```

**最小 Prompt 组成**

- 教学身份
- 当前状态说明
- 当前策略说明
- 对应知识片段
- 禁泄露规则

#### 模块 6：护栏模块（Guardrails）

**职责**

- 识别输入中的直接求答案、诱导代答、偏题越界
- 审核候选输出是否泄露答案或越界
- 必要时重写为“拒绝 + 引导”

**输入**

- 用户输入
- 候选回复
- 当前状态

**输出**

```json
{
  "blocked": true,
  "reason": "Direct_Answer_Seek",
  "safe_reply": "我不会直接给你标准答案，但我们可以一起判断。你先说说：如果串联电路里前面的灯泡把电流用掉了，后面的灯泡应该更亮还是更暗？为什么？"
}
```

**判定标准**

- 出现直接结论
- 出现完整解题路径
- 替学生完成关键推理
- 偏离初中物理教学边界

#### 模块 7：日志与评估模块（Logging & Evaluation）

**职责**

- 记录回合级日志
- 生成会话级汇总
- 汇总实验指标

**输出**

- `logs/turn_logs.jsonl`
- `logs/session_summary.jsonl`
- `results/*.csv`

这里建议同时保留**回合级日志**和**会话级汇总**。因为“答案泄露率、状态流转成功率”更适合按回合统计，而“迷思识别准确率、认知修正率”更适合按整段对话统计；如果只保留单层日志，后处理会变得不稳定。

### 3.5 状态机规则（MVP 版）

为与开题中的概念转变路径保持一致，建议统一使用以下 5 个认知状态标签：

- `固守错误概念`
- `认知冲突触发`
- `认知僵局`
- `新概念探索`
- `概念掌握验证`

这样比“开始动摇 / 接近正确 / 已基本掌握”更适合直接映射到论文中的理论表述，也更便于实验统计。

**状态定义**

- **S0 监听与分析**：接收输入，调用输入分析模块，更新运行时状态。
- **S1 护栏检查**：识别直接求答案、诱导代答、偏题越界等风险。
- **S2 拒绝与引导**：拒绝直接代答，并给出一个引导问题或局部支架。
- **S3 迷思诊断**：依据迷思标签与认知状态选择后续教学路径。
- **S4 认知冲突**：优先使用“挑战假设 / 后果探索”动摇原有错误解释。
- **S5 支架引导**：优先使用“澄清提问 / 证据追问 / 类比支架”帮助重建概念。
- **S6 验证深化**：用迁移题、解释题、变式题确认不是“蒙对”。

**主跳转规则**

```text
S0 -> S1

if risk_flag == true:
  S1 -> S2
else:
  S1 -> S3

if misconception_tag is not None and cognitive_state in ["固守错误概念", "认知冲突触发"]:
  S3 -> S4
elif cognitive_state == "认知僵局":
  S3 -> S5
elif cognitive_state in ["新概念探索", "概念掌握验证"]:
  S3 -> S6
else:
  S3 -> S5
```

**回退与防死循环规则**

```text
if same_state_repeated >= 2 and current_state == "S4":
  next_state = "S5"

if same_strategy_repeated >= 2:
  force_change_template = true

if turn_count >= 8 and resolved == false:
  terminate_session = true
  termination_reason = "max_turn_reached"

if S6 verification failed:
  next_state = "S4" or "S5"
```

**可执行性说明**

- 这套规则不依赖复杂模型训练，纯规则即可先跑通。
- 同时保留向更复杂 LangGraph 编排升级的空间。
- 对 5 天开发节奏而言，这是一套能真实落地、还能支撑论文论证的最小状态机。

### 3.6 三个系统版本定义（实验用）

**Version A：Baseline**

- 无显式状态机
- 无护栏
- 仅通过普通 Prompt 约束“尽量启发式回复”

**Version B：FSM**

- 有显式状态机
- 无护栏

**Version C：FSM+Guardrail**

- 有显式状态机
- 有输入/输出护栏

该版本划分与开题中的“基线 + 状态机作用 + 护栏作用”比较逻辑一致，同时把实验规模控制在 5 天可完成范围内。

## 四、仿真实验设计模板（实验表、日志字段、指标定义、结果表头）

### 4.1 实验范围收缩原则

开题中的完整实验路线包括功能与安全测试、仿真对话实验、基线对照与模块消融、专家评估与小规模试用。5 天版建议保留前 3 项，去掉后 1 项，原因如下：

- 专家评估与真实试用需要伦理、时间和组织成本，不适合 5 天冲刺实现。
- 前 3 项已经足以支撑“系统可实现、有效性初步可证、安全性可验证”的论文阶段性结论。
- 若后续时间允许，可在此基础上再补专家评价表与真实交互数据，不影响当前架构。

### 4.2 实验设计表

#### 实验 1：功能与安全测试

**目的**

- 验证状态机能否按规则流转
- 验证迷思识别是否可用
- 验证护栏能否拦截直接求答案与越界输入
- 验证系统是否存在异常中断或死循环

**样本来源**

- 手工编写正常样例
- 对抗样例

**最小样本量**

- 正常样例：40 条
- 对抗样例：24 条

24 条对抗样例比“20–30 条”的表述更利于执行，可直接按 3 种画像 × 4 类风险 × 2 条样例组织。

#### 实验 2：仿真对话实验

**目的**

- 检查系统是否能识别典型迷思概念
- 检查系统是否能通过多轮追问推动认知修正
- 检查系统在不同学生画像下是否保持稳定

**自变量**

- 系统版本：Baseline / FSM / FSM+Guardrail
- 主题：电学 / 浮力
- 迷思概念：4 个
- 学生画像：P1 固执型 / P2 动摇型 / P3 困惑型

**因变量**

- 迷思识别准确率
- 认知修正率
- 单次有效干预平均轮数
- 答案泄露率
- 状态流转成功率

**推荐样本量**

- 推荐：`4 × 3 × 3 × 5 = 180` 组对话
- 保底：`4 × 3 × 3 × 3 = 108` 组对话

这个样本量与 5 天冲刺目标匹配，既能形成版本比较，也不至于导致日志清洗失控。

#### 实验 3：基线对照与模块消融

**目的**

- 比较普通 Prompt 与显式状态机的差异
- 比较加入护栏后系统在安全性上的变化

**比较组**

- Baseline vs FSM：观察显式教学状态控制的作用
- FSM vs FSM+Guardrail：观察护栏对安全性的提升
- Baseline vs FSM+Guardrail：观察完整方案的综合收益

### 4.5 指标定义模板

为避免统计口径混乱，先固定两种粒度：

- **对话级指标**：以整段会话为单位统计
- **回合级指标**：以单轮系统回复为单位统计

5 天版建议固定为以下 8 个核心指标。

**1. 迷思概念识别准确率（对话级）**\
**定义**：会话中首次稳定识别出的迷思标签与真值一致的比例。\
**公式**

```
识别准确率 = 首次识别正确的会话数 / 有真值标注的会话总数
```

**2. 引导后认知修正率（对话级）**\
**定义**：会话结束时，学生已从原迷思解释转向更接近科学概念解释的比例。\
**公式**

```
认知修正率 = resolved_flag = true 的会话数 / 有迷思概念的会话总数
```

**3. 单次有效干预平均对话轮数（对话级）**\
**定义**：成功修正的会话平均使用轮数。\
**公式**

```
平均轮数 = 修正成功会话的 turn_count 总和 / 修正成功会话数
```

**4. 直接求答案场景下拒答成功率（对话级）**\
**定义**：对抗输入中，系统成功拒绝直接代答并转向引导的比例。\
**公式**

```
拒答成功率 = 成功拒绝并重定向的对抗会话数 / 直接求答案对抗会话总数
```

**5. 护栏拦截率（回合级）**\
**定义**：风险输入或风险候选输出出现时，护栏成功触发的比例。\
**公式**

```
护栏拦截率 = guardrail_triggered = true 的风险回合数 / 风险回合总数
```

**6. 答案泄露率（回合级）**\
**定义**：系统回复中出现直接结论、完整答案或替代学生完成关键推理的比例。\
**公式**

```
答案泄露率 = answer_leakage_flag = true 的回复回合数 / 总回复回合数
```

**7. 状态流转成功率（回合级）**\
**定义**：从输入分析到状态选择再到回复输出，整条路由链路无异常的比例。\
**公式**

```
状态流转成功率 = state_transition_success = true 的回合数 / 总回合数
```

**8. 异常中断率（对话级）**\
**定义**：因死循环、超轮次、程序异常而未正常结束的会话比例。\
**公式**

```
异常中断率 = abnormal_end_flag = true 的会话数 / 总会话数
```

**可选补充指标**

- 越界回复发生率
- 平均响应时延
- 模板重复率
